# daily checker

나만의 데일리 루틴을 YES / NO로 기록하는 iOS·Android 공용 앱입니다. Expo SDK 58, React Native, TypeScript로 구현했으며 같은 코드로 웹에서도 실행할 수 있습니다. 로그인이나 서버 없이 기기에 기록을 저장합니다.

먼저 내 컴퓨터나 휴대폰에서 실행하려면 [로컬 테스트 안내](LOCAL_TEST.md)를 보세요. App Store 배포는 현재 보류 중입니다.

## 실행

Node.js 22.13+/24.3+/26+ 계열과 npm이 필요합니다. 이 환경에서는 `.nvmrc`에 고정한 Node.js 24.19.0을 사용했습니다.

```bash
git clone --branch main https://github.com/jh555n/dailychecker.git
cd dailychecker
npm ci
npm start
```

로컬 컴퓨터에서는 저장소를 받은 디렉터리에서 같은 명령을 실행하세요. Expo Go의 SDK 58 호환 버전으로 QR 코드를 스캔하거나, 설치된 에뮬레이터를 사용합니다. 클라우드의 개발 서버에 실제 기기가 자동으로 연결되는 것은 아닙니다. 실제 기기 검증은 접근 가능한 로컬 개발 환경에서 진행하세요.

```bash
npm run web       # 웹 개발 서버
npm run ios       # macOS + Xcode iOS 시뮬레이터 필요
npm run android   # Android SDK + 실행 중인 에뮬레이터 필요
```

## 사용 방법

1. **루틴 관리**에서 나만의 루틴을 추가합니다. 이름, 색상, 심볼을 바꿀 수 있습니다. 기본 루틴은 금주·금연·운동이며, 예시 기록은 넣지 않았습니다.
2. **나의 기록**에서 날짜를 선택하고 **기록 남기기**를 누릅니다.
3. 각 루틴을 YES 또는 NO로 선택한 후 저장합니다. 선택하지 않거나 **선택 해제**하면 미기록으로 남습니다.
4. 월/주 보기를 전환하고 과거 날짜를 선택해 기록을 추가하거나 수정할 수 있습니다. 미래 날짜는 기록할 수 없습니다.
5. **돌아보기**에서 루틴별 이번 주 기록, 현재/최장 연속일, 전체 YES 일수를 확인합니다.

캘린더의 색상 DOT은 YES 기록입니다. NO만 있는 날은 `−`로 표시하며, 날짜의 접근성 레이블에는 YES와 NO 개수가 모두 포함됩니다. 선택한 날짜의 목록에서도 각 루틴의 YES/NO/미기록을 확인할 수 있습니다. 루틴 삭제는 확인 후 해당 루틴의 모든 기록을 함께 삭제합니다.

## 연속일 규칙

| 상황                       | 계산                                            |
| -------------------------- | ----------------------------------------------- |
| 오늘 YES                   | 오늘부터 과거로 이어지는 YES 개수               |
| 오늘 NO                    | 즉시 0일                                        |
| 오늘 미기록                | 어제까지 이어지는 YES 개수 유지                 |
| 지나간 날이 NO 또는 미기록 | 해당 날짜에서 연속이 끊김                       |
| 과거 기록 수정/선택 해제   | 현재 및 최장 연속일을 원본 기록에서 즉시 재계산 |

예를 들어 25·26일 YES이고 27일 미기록이면 2일입니다. 27일을 NO로 저장하면 0일, YES로 저장하면 3일입니다. 28일까지 27일이 미기록으로 남으면 0일입니다. 루틴별로 독립적으로 계산하며, 과거 날짜를 선택해도 목록의 **현재 N일 연속**은 오늘 기준입니다.

날짜 키는 UTC가 아닌 기기의 현지 달력 날짜를 사용합니다. 앱이 실행 중이면 15초 간격 및 앱 복귀 시 날짜를 갱신합니다. 기존 기록의 날짜 키는 시간대를 바꿔도 이동하지 않습니다. 월·주 캘린더는 월요일 시작입니다. 주말도 연속일에 포함됩니다.

## 저장과 오류 처리

- `@react-native-async-storage/async-storage`를 사용합니다. 네이티브에서는 앱 저장소, 웹에서는 해당 브라우저·사이트의 localStorage에 저장됩니다.
- 저장에 성공한 뒤 화면 상태를 반영합니다. 실패하면 입력창을 유지하고 오류를 표시합니다.
- 저장된 JSON이 손상되거나 알 수 없는 버전이면 자동 초기화하지 않고 기존 데이터를 보존합니다.
- 앱 삭제, 앱 데이터 초기화, 브라우저 데이터 삭제 시 기록이 사라질 수 있습니다. 기기 간 동기화·백업·암호화 저장은 포함하지 않습니다.
- 기록 저장을 위한 외부 서버 전송은 없습니다. 개발 서버 없이 실행하는 설치형 앱 제작은 별도 네이티브 빌드가 필요합니다.

## 검증 명령

```bash
npm run typecheck
npm test
npm run test:ui
npm run build:web
npm run build:bundles
```

UI 테스트는 Chromium을 사용하고, 필요하면 Expo 웹 서버를 자동 실행합니다. 이 클라우드 환경에서는 `/usr/bin/chromium`을 자동 사용합니다. 다른 환경에서는 `npx playwright install chromium`으로 Playwright 브라우저를 설치하세요. `PLAYWRIGHT_CHROMIUM_PATH`로 별도 Chromium 경로를 지정할 수도 있습니다.

테스트는 날짜를 2026-10-27, 시간대를 Asia/Seoul로 고정합니다. 기본 로직 테스트는 연속일, 과거 수정, 윤년/연도/DST 경계, 미래 기록 차단, 저장 데이터 검증을 확인합니다. 브라우저 테스트는 실제 화면을 통해 입력·수정·삭제·재로딩·자정 갱신·저장 오류·반응형 화면·접근성을 검사합니다.

`build:bundles`는 iOS/Android용 JavaScript/Hermes 번들 검사입니다. Xcode/Gradle 네이티브 컴파일, IPA/APK/AAB 생성, 실제 기기 테스트나 스토어 배포를 뜻하지 않습니다.

| `tests/browser/journal.spec.ts` | 브라우저 기능·접근성 테스트                    |

## Apple App Store 배포 준비

iOS 릴리스 프로필, 앱 아이콘, 앱 내 개인정보 안내와 심사 자료를 추가했습니다. 계정·서명·공개 URL이 미확정이므로 실제 제출은 아직 하지 않았습니다. [배포 절차와 현재 차단 항목](release/README.md)을 확인하세요. `npm run release:assets`는 준비된 자료를 검사하고, `npm run release:check`는 남은 제출 조건을 표시합니다.
